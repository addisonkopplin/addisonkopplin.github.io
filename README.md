# addisonkopplin.com (v2 playground)

Plain static site for GitHub Pages (user-site root, `CNAME` = addisonkopplin.com).
There is no build step at runtime. All links are relative, except in `404.html`, which uses root-absolute links because Pages serves it from any missing path.
There are no external requests: the font (IBM Plex Mono, OFL, see `assets/fonts/OFL-IBMPlexMono.txt`) and all scripts are self-hosted.

```
index.html              playground home (experiment grid + live fractal tree)
resume.html             resume (links Addison_Kopplin_Resume.pdf)
play/                   one page per experiment
  string-art.html       EXP-001
  fractal-tree.html     EXP-002
  hardware.html         HW-001..003
  data/                 precomputed data the experiments load
assets/style.css        the whole theme (colours are CSS variables in :root)
assets/js/site.js       shared (UTC clock in the top bar)
assets/js/*.js          per-experiment scripts, plain <script> tags, no modules/bundler
assets/img/, fonts/     images and the self-hosted font
404.html, favicon.svg, CNAME
```

The pages are generated by `/workspace/resume-src/build_v2.py`, which reuses the resume data in `build_site.py`.
You can edit the HTML directly instead; the generator is a convenience, not a requirement.

## Adding a new experiment

1. **Pick an ID.** Use the next `EXP-00N` for code experiments or `HW-00N` for hardware.
2. **Create `play/<slug>.html`.** The easiest way is to copy `play/fractal-tree.html` and change:
   - the `<title>` and the meta description;
   - the `.tag` breadcrumb (`playground / EXP-00N`), the `<h1>`, and the `.sub` intro;
   - the footer sheet label (`sheet NN / NN · EXP-00N`).

   Keep the `../` prefixes, because the page lives one folder down.
3. **Add the page's script.** Put it in `assets/js/<slug>.js` and include it at the bottom of the page with `<script src="../assets/js/<slug>.js"></script>`.
   - Put any data it needs in `play/data/`. Load it as a `.js` file that sets a global (see `einstein-tongue-nails.js`), so it also works from `file://`.
   - Respect `prefers-reduced-motion`: no auto-playing animation; show the final state instead.
4. **Use the existing building blocks:**
   - `.panel` + `.panel-head`: an instrument frame with corner ticks and a live readout;
   - `.controls` / `.ctl` with `<label>` + `<output>` + `<input type=range>`: sliders;
   - `.prose`: the write-up;
   - `.spec`: a parameter table;
   - `.entry`: log items.
5. **Link it from the home page.** In `index.html`, copy one `<a class="exp">` card inside `<section class="exps">`, then set the href, thumbnail, ID, tech tag, title, and one-sentence description. Update the "N entries" count in the section rule.
   - Thumbnail: an inline SVG or a small image (aim for under 60 KB) in `assets/img/`. The card crops it to 16:10.
6. **Check before publishing:**
   - Preview with `python3 -m http.server` from this folder.
   - Screenshot at 1280 and 390 wide (`/workspace/resume-src/shots_v2.sh`, add the page to its list).
   - Keep the folder under ~1.5 MB.
   - Run `/workspace/resume-src/check_v2.sh`, which must print `clean` (no email address or phone number anywhere).
